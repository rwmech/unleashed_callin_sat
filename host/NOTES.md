# How these tests are built, and what it has already cost to learn

**Applies to versions:** gateway sat firmware 0.1.0 (phase 1). Written 2026-10-05.

This is the reasoning behind `host/`, kept here rather than in commit messages because the next person
to add a suite needs it and nobody reads a commit message from six months ago.

## The two rules

**1. Every test must fail against the code before its fix.** A test written after the fix that passes
immediately has proved nothing. The parent project has shipped tests that *agreed with the bug* more
than once — most memorably a suite that asserted "a deleted handle is new again", which was the bug,
so the test and the code were written from the same wrong idea and held each other up for years.

**2. Do not write a client that agrees with your own implementation.** The parent project lost two
rounds to a telnet test client written beside the server: it sent raw bytes and doubled `0xFF` the way
the board did, so every test passed while the hardware failed — once on binary negotiation and once on
CR padding. Its recorded conclusion is the rule:

> when a protocol is involved, test against somebody else's implementation. A client written next to
> the server tests that the two agree, not that either is right.

There is no `lrzsz` for DNS or telnet, so the next best thing is used here: the encoders are written
from the RFCs' own wire formats and prose, quoted in the comments, and the expected bytes are spelt
out as literals rather than produced by calling the code under test. `telnet.h`'s command codes are
*duplicated* from RFC 854's table and then asserted equal — the duplication is the point, because a
renumbered constant would otherwise be invisible.

## `make break`, and why its own self-check matters more than it does

`make break` compiles each suite once per `GW_TEST_BREAK` value, each value removing exactly one guard
from the code under test, and **refuses to pass unless something catches every one**. That is how rule
1 is kept without time travel: you cannot run a test against code that predates it, but you can run it
against code with the guard taken back out.

A guard can be proved three ways, and the run says which:

- **a check fails** — the usual case;
- **the code hangs** — the proof for a clamp whose absence leaves a consumer waiting for bytes that
  never arrive. The break run is timed out and the timeout *is* the proof;
- **ASan trips** — the only proof available for a guard whose whole job is to stop an out-of-bounds
  *read*, where what gets read is whatever is next in memory and no verdict need change.

**And the first version of `make break` reported "EVERY GUARD HAS A TEST" having tested none.** It
built its case list with `eval echo \$BREAK_$u`, looking for a *shell* variable of that name; the make
variables were never in scope, the list was empty, the loop body never ran, and the target printed
success. **The thing that verifies the tests was itself vacuous.**

That is worth more attention than any single guard it proves. The list is generated by make now and
the case count is asserted, so a list that comes out empty fails loudly. The general shape, which is
this project's own recurring one at one remove: **silence reading as success is exactly the failure a
proof like this exists to prevent, so the proof needs its own proof.** Any future check that reports
"all clear" should be asked how it behaves when it is given nothing to check.

### What it has caught

Five tests passing for the wrong reason, four of them written by the same person who wrote the code:

- **every compression-pointer test was a short packet.** With the pointer guard removed, the `0xC0`
  ran off the end of the packet and the *name-never-terminates* guard refused it instead. The tests
  proved the packet was refused without proving which check did it. The discriminating packet has 192
  octets of padding after the `0xC0`, so a parser without the guard walks over them, finds a root
  label and a well-formed question, and answers something nobody asked.
- **the truncation sweep sliced a long-lived buffer.** A read past the end was still inside the
  allocation, returned a neighbouring octet, and something further down refused the packet for an
  unrelated reason. Exactly-sized allocations now, which makes the same read a real overrun and, under
  ASan, a crash.
- **the QTYPE/QCLASS guard** needed a packet with a valid A/IN sitting just past the length handed in,
  rather than whatever the heap happened to contain.
- **the ring's drop clamp was tested by dropping 99 from a ring of 32** — and 99 past the tail lands on
  a multiple of 32, so the mask hid the clamp's absence entirely: `used()` read 0 and `room()` read 31,
  both right *by accident*. It is tested at every over-amount from 1 to twice the size now. **A guard
  tested only at a value where its absence is invisible is not tested.**
- and `make break` itself, above.

## Three bugs the harness found in the code

**`isYes("off")` returned `true`.** It tested the first letter against a set containing `y`, `Y`, `1`,
`o`, `O`, `t`, `T` — and "off" shares its first letter with "on" — so a sysop switching a role off
switched it on. Found by feeding it the spellings a form actually sends.

> **A prefix test over a set of words is only safe while no word in the set is a prefix of a word
> outside it, and nothing tells you when that stops being true.**

That is the generalisation worth carrying. The fix is a whole-word compare, which costs nothing and
cannot rot.

**`#if` cannot see an enumerator, and that compiled every DNS guard out of the firmware.** The break
switch was first written as an `enum`, so every `#if GW_TEST_BREAK != BREAK_x` compared 0 against an
unknown identifier — which the preprocessor reads as 0 — the condition was false, and **every bounds
check in the DNS parser was removed from the shipping image**, not merely from the tests. On an open
network, parsing packets from anyone in radio range.

It was caught in under a minute by `-Werror` on an *unused parameter*, because removing the last check
left `cap` unread. Nothing aimed at it found it. That is the whole argument for `-Wall -Wextra -Werror`
on a test suite: a suite that tolerates a warning will tolerate the warning that was the bug. Every
break switch in this repo is `#define` now, and each one says why in a comment.

**A refusal that says nothing.** `ap_dtim` refused with the six characters "1 to 3", which tells a
sysop neither what is wrong nor why it matters. The suite now asserts that every refusal is a sentence
of at least eight characters, at most ninety so it fits a 40-column form's note, and free of control
bytes because it reaches an HTML page. That was already the project's standard for a refusal; now
something enforces it.

## Which units are here, and why those

The four that **parse something somebody else sent**, which is the whole selection rule:

| Unit | Where its input comes from |
|---|---|
| `dnsparse.h` | anyone in radio range of an open access point |
| `telnet.cpp` | the board, and whatever is on the far end of a mistyped address |
| `settings_rules.h` | text a stranger typed into a form |
| `ring.h` | not parsing, but the one lock-free thing, carrying every caller's keystrokes |

The pure halves are lifted into headers with no platform in them — the shape the parent project uses
for `forums_ptr.h`, `panel_photo_fit.h` and `satsched.h` — so the tests drive *exactly the code that
ships* rather than a copy of it. The `.cpp` keeps the sockets, the tasks and NVS.

**Still with nothing behind it, and the right next job:** `web.cpp`'s cookie reader, its
form-body decoder and `pathIs`. They take bytes from the same strangers the DNS responder does.
`pathIs` in particular exists because of a bug worth remembering — `req->uri` holds the whole URI
including the query string, so a `strcmp` against a path 404'd every request carrying one, which
silently killed the entire access-point role while reading as obviously correct.

## Known gaps, decided rather than overlooked

**A console reader. Queued, not built — Rob's call, 2026-10-05.**

The portal is the *only* way to change a setting on a gateway: the console is write-only, and there
is no `set key value` path on UART0. That is why the access point defaults on (see `settings.h`,
where the default and the reason sit together), and the two are coupled — the portal being the only
way in is what makes defaulting it on necessary.

The reasoning for leaving it out is sound and worth preserving: **a gateway on a post has no console
at all**, so the portal is the right way in regardless, and building a second path first would be
building for the case that does not happen. But the case that *does* happen is a gateway on a bench
whose Wi-Fi settings got mangled — and for a board, that is exactly what USB and Improv are for.
Without the equivalent here, the recovery story is `pio run -t erase`, because NVS survives an
ordinary reflash and takes the broken settings with it.

So this is a **decision to revisit, not an omission to rediscover**. If it is built, the shape is a
few lines reading lines off UART0 and calling `settings::set` — which is already the one validator
and already returns a sentence to print, so almost nothing new is needed. `host/test_settings.cpp`
covers the hard half of it today.

A smaller, cheaper partial worth weighing at the same time: the HTTP server only starts when the
access point is up, so a gateway with the access point off but a station joined to a house router has
no portal either, even though it is on a reachable network. Starting the server in that case would
make the all-roles-off state recoverable over the house network for anybody who had set a password.
It also widens what is served on the house LAN, which `web.cpp`'s `onOwnAp` already has an opinion
about. Not done; named here so the trade is visible.
